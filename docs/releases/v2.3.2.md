# Pellet firmware v2.3.2

**Not released.** Eight bug fixes ported one by one from upstream
(Mouse-GYM/auto-trainer-hardware `main` at `2713e7b`) onto v2.3.1. The pellet
and magnet images build with no warnings. On 2026-11-10 the rig's v1.2 board
passed all seven v1.2 checks on this image (see "Rig run, 2026-11-10"). Nothing
has run on a v1.3 board.

## Changes

1. **TMC2209 UART lock.** The three stepper drivers share one UART. The CAN
   handlers on the main thread and the motor work queue reach it, and so does
   the shell. The first two are cooperative and never yield in the middle of
   an exchange, so they could not corrupt each other even on v2.3.1. The
   preemptible shell can, though: an `adi_tmc2209` or `motor_math` shell
   command running during the re-home driver proof on a v1.3 board could fail
   that attempt on a healthy driver, and two failed attempts refuse motion
   with `-EIO` until a reboot. A mutex now covers each register exchange, the
   microstep read-modify-write and the whole driver proof. Register writes now
   report a failed echo instead of always 0. Init, config writes and the
   driver proof keep their outcome and only log it (`IHOLD_IRUN rewrite failed
   its echo check`); the shell's `adi_tmc2209 write` prints and returns it.
   The lock can make a CAN command wait behind a shell register access (about
   10 ms per access), or a fault check wait behind a microstep write (up to
   about 20 ms).
2. **Long servo moves.** A servo move longer than about 15.4 s (three 256-sample
   blocks at 20 ms) stopped short of its target, because the refill compared
   against the stepper buffer size. It now runs to the end. Moves shorter than
   10.24 s never refill and are unchanged.
3. **Tone ACK.** A tone command that fails to play gets one ACK, with its error.
   Before, it got ACK 0 first and then the error. A failed play also aborts the
   tone that was playing, and that earlier tone's command now gets its ACK 0.
   On v2.3.1 its uuid was overwritten and it was never ACKed.
4. **FIXED_XYZ save.** A `STEPPER_MOVE` with `save` set and a NaN or infinite
   position is refused with `-22` (`EINVAL`) and nothing is stored. Before, it
   was saved and ACKed 0: a NaN or an absolute infinity made every later
   `FIXED_XYZ` skip that axis and still ACK 0, and a relative infinity was
   clamped to 0 or 15 turns and saved.
5. **Refill guards and homing block bounds.** A servo or stepper refill now
   returns at once if the move was already stopped. The stop paths already
   cancel a scheduled refill, so this is a defensive guard for the window
   between that cancel and the stop being marked done. A homing block now has
   at least 1 pulse and at most 65535 timer ticks per pulse. At reachAQ's
   settings (24 steps/rev, microsteps 8, 200 kHz, about 12.3 turn/s) a block
   is 236 pulses of 85 ticks, as before.
6. **Stop sequence.** Stopping a motor's DMA, its stepper counter and purging
   its block queue now happen with interrupts locked, so the DMA completion
   interrupt cannot reload a block in the middle.
7. **Servo start pulse.** A move on a servo whose timer is already running no
   longer starts with one pulse of up to twice the intended width. Its first
   sample loads on the next 20 ms period instead. Steppers are unchanged.
8. **Bootloader responses.** Responses are zeroed instead of carrying stack
   bytes. `VERSION` reports slot 1 as `0.0.0` when its header cannot be read. A
   failed page erase is answered with a bootloader `NACK` instead of a generic
   ACK with a stale uuid. The data ACK reports `active` and `bytes_written`.
   `jerrycan_updater` reads only the response type, so updates work as before,
   and an erase failure still fails the update after its 1 s timeout.

Otherwise v1.2 and reachAQ behavior is unchanged. No frame, layout, capability
bit or status bit changed, and `JERRYCAN_WIRE_SCHEMA_VERSION` stays `1`. The
new values on the wire are the `-22` ACK for a non-finite save, the ACK 0 for a
tone aborted by a failed play, the bootloader `NACK` for a failed erase, and
the zeroed response bytes. All of v2.3.1's known limitations still apply;
limitation 4 (a limit-switch stop leaves the stepper counter running) is
deliberately kept.

Left as found: a non-finite position saved by v2.3.1 or older stays stored and
still makes `FIXED_XYZ` skip that axis. Re-save the `FIXED_XYZ` positions.

## Verification so far

- Pellet image: 0 compiler warnings (the three CMake "No SOURCES given"
  notices are the same as at v2.3.1). Against v2.3.1: text 219656 to 220160
  (+504), data 37017 to 37037 (+20, the bus mutex), bss 39016 unchanged.
- Magnet image: links, 0 compiler warnings.
- Host tests: `stepper_power_policy_test`, 17 passed. None of the eight changes
  is in a module the host tests build, so each is compile-checked only.
- An independent review of every commit found no code defect and no change to
  v1.2 or reachAQ behavior beyond the items above.

### Rig run, 2026-11-10

On christielab10's v1.2 board, the image from `99f1a62` (reporting
`2.3.1-g99f1a62`, untagged), run log `/tmp/v232-rig-run-20261110-180510/run.log`:

- **Flash in:** from v2.3.0 with `flash_pellet_module.sh --allow-unqualified`.
- **Setup:** all five motor configs written and verified; `FIXED_XYZ`
  positions saved at 2.0 turns per axis, each ACK 0; the ESTOP probe answered
  `-1`.
- **The seven v1.2 checks** (`hil_stepper_power_check.py`, unchanged since
  v2.3.1): 7 PASS, 0 FAIL, 0 SKIP, with 42 ACKs matched to the commands sent.
  - `status_idle`: every `status` byte 0.
  - `home_and_move`: homes in 0.0 to 0.1 s, and a +1 turn in 0.2 to 0.3 s.
  - `estop_multiblock_restart`: ESTOP at 0.60 s, ACK `-EPERM` at 0.64 s.
  - `recover_at_limit`: passed.
  - `fixed_xyz_interrupted`: one `-EPERM`.
  - `servo_after_estop`: servo 1's move ACKed 0 after 1.54 s of 1.50 s
    planned.
- **Flash out, back to v2.3.0, using this image's bootloader:**
  `reachaq-update --2.3.0` succeeded on the first attempt. The updater read
  "Running 2.3.1, Slot1 2.3.0" from this image's `VERSION` response before
  sending, and "Running 2.3.0, Slot1 2.3.1" after.
- **After the restore:** config rewritten and verified; capabilities and
  `home_and_move` passed.

On a board, still to show:
- a servo move over 15.4 s that reaches its target;
- one normal pulse at the start of a servo move (scope);
- a homing block's numbers, measured rather than inferred from the homes
  passing;
- on a v1.3 board, the driver proof passing during a re-home while the shell
  loops `adi_tmc2209 dump 0`. That can fail on v2.3.1, and should not on this
  image.
