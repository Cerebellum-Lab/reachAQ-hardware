# Pellet firmware v2.1.0

Release date: 2026-09-15

Source tag: `v2.1.0`<br>
Source commit: `161b635d9768ef500d84bf93e423e90643e6e13f`

## Changes

- Add two FSR pressure sensor streams to the pellet board.
  - Stream `instance = 0`: connector `J11`, `PA0`, `ADC1_IN1`.
  - Stream `instance = 1`: connector `J21`, `PA6`, `ADC2_IN3`.
  - Both sample at 80 Hz and transmit as `JERRYCAN_CMD_PRESSURE_READ`.
- Enable `adc1` (`adc1_in1_pa0`) and `adc2` (`adc2_in3_pa6`).
- Remove `ext_button_1` to free `PA0`.
- Remove `analog_out` and disable `dac2` to free `PA6`.
- Exclude the pressure driver from the MCUboot image, matching the magnet board.

The two sensors are deliberately placed on separate ADC peripherals. The driver
runs a continuous asynchronous sequence that never releases the ADC context
lock, so two sensors on one ADC would deadlock the second instance during
`POST_KERNEL` init. See
[Pellet board pressure sensors](../pellet-pressure-sensors.md).

## Behavior changes

- `JERRYCAN_CMD_DOOR_SENSOR.external_button` is retained in the message layout
  but is now always `0`. The pellet board no longer has an external button.
- The pellet board no longer answers `JERRYCAN_CMD_ANALOG_OUT` commands and no
  longer publishes analog-out status. `dac1`, used by the tone generator, is
  unchanged.
- All v2.0.0 tone-to-stimulus behavior is unchanged.

## Acceptance criteria

- Firmware version request reports `2.1.0` after reboot and finalization.
- `JERRYCAN_CMD_PRESSURE_READ` arrives for both `instance = 0` and
  `instance = 1`.
- Each stream's value tracks its FSR: a stable raw 12-bit count, 0 through 4095,
  that changes when that sensor is pressed.
- Tone behavior is unchanged from v2.0.0:
  - No tone: `STIM0=0`, `STIM1=0`.
  - 5 kHz Tone 1: `STIM0=1`, `STIM1=0` for the tone interval.
  - 6 kHz Tone 2: `STIM0=0`, `STIM1=1` for the tone interval.
  - Any other tone frequency: `STIM0=0`, `STIM1=0`.
